# 可重放工程交付规范

除两条 MP4 和原有 JSON 外，必须提交：

- `project.drp`：真实导出的 Resolve 工程，含两条时间线。保留可编辑合成关系；不得只有外部烘焙绿底成片。
- `README.md`：版本/版本类型、内部脚本或 GUI 路线、时间线名称、重链接步骤、色彩与 alpha 设置、方法和局限。记录查阅的官方文档章节与一处应用；不要求不相关的音频教程。
- `assets/`：实际使用且题包未提供的所有 mask、alpha 前景等中间素材；未用可不创建。引用原题包素材无需重复复制。
- `scripts/`：实际构建工程/合成的脚本（如有）；GUI 路线不要求此目录。

submission.json 的 `project_file` 固定为 `project.drp`，`readme` 固定为 `README.md`；每个 clip 填 `timeline_name` 与真实 `render_job_id`。输入输出帧号一对一。

评测端将 DRP 导入独立项目，依 README 重链接题包和 assets，检查前景、mask/alpha、绿底关系，重新渲染两条完整视频。核对帧数、帧序、格式及画面内容，匹配原始轨迹、job 与哈希。重渲染编码字节可能不同，不要求 MP4 SHA256 相同；视觉容差须用同环境重复渲染校准，未知时标待核实。

在复制工程中改绿底应能改变背景而不替换整条烘焙视频；这是一个可编辑性核查方法，不规定节点数量。仅凭 DRP 存在、截图或自报 job ID 不能判合规。

缺 DRP/README 或空文件记交付不完整。工程打不开、缺依赖、不可编辑或烘焙伪装由独立审阅给出证据。质量原始分与软件合规分别报告，不重复扣一次总分。桥接、插件等故障先区分是否属于出题端环境问题。
