# 第6题：把93分钟剧情长片做成可发布的中文解说

你是影视解说剪辑师。请把 `input/source.mp4`（《Valkaama》，Tim Baumann 导演，Michael Georgi 配乐版本）制作成 **510–570秒**、面向未看过原片观众的中文剧情解说成片。允许剧透。必须实际交付可播放的视频、中文旁白、原声轨、字幕和可重建时间线，仅提交脚本或剪辑计划不能通过。

解说需要交代人物处境和动机、寻找与同行、关键真相/选择、最终结果四个阶段；至少讲清 **3条源片证据相隔180秒以上的因果联系**。既要压缩故事，又要区分实际发生的事件、角色的说法/谎言和你的解读，不能把推测写成镜头已经证明的事实。必须覆盖影片最后的无对白行动，不得用网络梗概代替视听核实。允许辅助检索和使用字幕工具；最终证据必须落到提供的这个版本。

采用 **40–90个、每个2–20秒的原速源片片段**，可重排但须让新观众理解。1280×720、25fps，等比缩放并补黑边；硬切，不改色、不裁切、不增补其他影片或AI生成镜头。画面烧录中文字幕。限定形式用于可重建验收，创作空间在取舍、排序、叙述、配音和原声使用。

旁白须有300–420秒实际中文发声；保留4–6段有叙事作用的原声对白，每段4–15秒，合计30–65秒。这些保护区间不得被旁白覆盖超过100毫秒，不能用无对白音乐段冒充。其余位置可压低或静音源片声音，不额外加外部音乐。旁白区间按句标注，允许句内300毫秒以内自然停顿；长停顿须拆开，不允许静音占时长。字幕最多两行，每行22个Unicode字符，每条1–7秒、至多9个非空白字符/秒，不重叠，不使用SRT样式标签。混音-16±2 LUFS、真峰值≤-1 dBTP。

把所有结果放进 `submission/`：

- `commentary.mp4`：H.264/AAC成片。
- `narration.wav`、`original_audio.wav`：与成片零点对齐、全长、48kHz双声道16-bit PCM；前者仅中文人声，后者仅按时间线剪接和调增益的原片声音。
- `zh.srt`、`script.md`：烧录字幕对应的SRT和完整解说稿。
- `timeline.json`、`source_map.json`、`claims.json`、`project.json`：按 `OUTPUT_CONTRACT.md` 提交。事实清单需覆盖15–60个实质性断言，每条指向实际旁白/画面位置和原片证据；至少3条因果不能只是时间先后。
- `README.md`：制作方法、工具版本、外部辅助资料链接和署名。影片为CC BY-SA 3.0；说明使用该片、导演、配乐版本、许可链接及改编。

可直接用随题的 `tools/render.py` 从你的时间线和旁白重建最终视频；也可以用剪辑软件制作，但必须交付同一声明式时间线且重建结果一致。没有剪映/Premiere/DaVinci的强制要求。不要上传或运行评测器目录；评测方只向你提供 `candidate/`。

评分为机器35分＋视听语义65分，详见 `SCORING.md`。总分≥80并通过所有技术及关键语义门槛才接受。评测会实际解码全部视频，重建和比较全部帧及音轨，听看成片并回查源片证据；不会仅凭你填的表格给分。
