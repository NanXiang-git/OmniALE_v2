# 第14题 / Case46 · 正式困难版：受限时间轴的电影口述影像

为 `input/source.mp4` 制作可独立关闭的中文口述影像，帮助双语视障观众跟上主体、动作因果与逐步出现的信息。主片264秒，保持所有原画面、帧数和时间轴；不得暂停、改速、删镜头或加黑场。交付可实际听看的媒体，不是只有策划文本。

## 材料与已知边界

- 主片：官方《Sintel》原片08:00—12:24连续段，1280×546、24fps、6336帧；声音为原声立体声下混、固定-4dB预衰减以避免下混削波、再转码。原片公开可检索，但测试仅可使用本包输入。
- `context.mp4`：原片03:15—03:55的40秒前情。假设观众已看/听过它；仅用来理解先前已知信息，**不能拼入提交**。它自己的0秒不等于主片0秒。
- `original.wav`：从题包主片解码的48kHz立体声float PCM原声；`reference_en.srt` / `reference_zh.srt`是辅助字幕，不能据“没有字幕”认定音效可覆盖。
- 观众能理解原英语对白，中文描述只补视觉信息。不要复述/翻译每句对白。不得通过外网剧情介绍或既有口述稿获知本片段尚未揭示的信息。

困难点在相似主体的持续区分、快速动作与短暂停顿、视觉线索的先后关系、情节声音与配乐之间的取舍。不要预先给人物/动物贴上片段尚未证实的身份，也不要把自己的心理解释写成画面事实。

## 必交输出

`accessible.mp4`、`mix.wav`、`base_track.wav`、`ad_track.wav`、`ad.vtt`、每条实际描述WAV、`ad_plan.json`、`selection_audit.json`、`player_config.json`、`rebuild.json`、README及离线重建脚本。JSON精确结构见 `submission_schema.json`。

- `ad_plan.cues[]`：唯一id、start、end、wav、visual_source_interval、knowledge_time、sound_risk。所有时间均主片相对秒。plan与VTT逐条一一对应，起止容差80ms；单条WAV长度与plan相差<120ms。`knowledge_time`是本句信息在主片最早可知的时刻，不能晚于该句开始；来自前情的已知信息记0，即使本句所引主片视觉区间较晚也可如此标记，但Judge必须在context中核实，不能把新的主片事件或身份揭示冒称为前情已知。非零knowledge_time须落在所引主片视觉区间内。视觉证据必须来自已提供材料，不能以“全片剧情已知”为理由提前揭示。
- `selection_audit.events[]`：至少10个自己辨识的视觉事件，每项有唯一id、visual_interval、decision（describe/omit）、cue_ids、reason、earliest_knowable、sound_risk_intervals。`describe`引用实际cue；`omit`不引用cue并说明取舍。不要为了凑数把一个事件拆成装饰细节。每个实际cue至少被一个describe记录引用。earliest_knowable同样允许经context验证的0例外，否则须落在visual_interval内，且不能晚于引用cue起点。一个cue可以服务多个事件，合理省略也可得分；裁判核看原片与实际声音，不按审计文字长度给分。
- 全长base/ad/mix均为48kHz立体声真实PCM WAV，时间轴从0开始；逐条WAV必须与实际AD轨对应，不能用静音占位。成片必须含实际混音。`ad.vtt`作为外挂字幕，不得烧录或用图形遮挡任何原画面；评分比较完整帧。
- base只允许相对题包原声采用**单一全局增益[-6,0]dB**，在`player_config.base_gain_db`声明。不得局部duck、动态压低、删改或创造空隙；选窗口、压缩措辞与调整AD响度来解决冲突。`mix = base + ad`，不能用未交付的额外声轨或总线处理绕过一致性。base及mix的上述双通道波形关系相对误差≤2%，全长差<80ms；实际AD发声至少97%落在VTT安排内。成片和mix真峰值≤-1dBTP（测量容差0.1dB）；为AAC编码留下余量。
- 描述语速以可懂为准，建议3—4.5汉字/秒；不得以异常加速塞入所有内容。事实可跨句建立，不要求照某个固定参考稿。
- 播放器将成片视频静音，分别同步base与AD，开关AD必须真实改变声音而不改变画面或进度。使用附带`player.html`检验；`pause_policy`固定为`fixed_timeline`。

## 评分与失败条件

100分：自动排程15、选择审计结构/引用10、一致性5、离线重建5；Judge信息取舍10、原声保护20、语言10；私有原子事实25。≥80且所有门槛通过才通过，事实覆盖≥85%。完整权重和接口在`rules.json`。

硬门槛包括：不能混淆关键主体/动作关系、不能提前泄露识别信息、不能用虚构心理或年龄数字代替视觉事实；不得实质掩蔽对白或关键动物/碰撞/动作/转场声音；不得靠暂停或改动时间轴；必须有真实、清晰、与字幕/计划相符的描述音频。私有事实是证据检查点，不是唯一口述答案。

Judge读取前情、主片、实际成片/独轨与审计；分窗听看后另做全片复核。两次独立判断，争议第三次仲裁；标注边界存疑必须查原视频，无法确定记pending。字幕边界和音效风险区域是线索，不是逐音素人工真值。没有实际音视频API或关键复核未完成时，总分为null，不用文字替代听评。

## 执行边界

只在独立submission输出；输入只读。全部产物、缓存和临时文件放D盘。建议150分钟、8核CPU/32GB内存、30GB工作盘，GPU可选；若主办方改变预算须提前公告。允许本地脚本、TTS和媒体工具，不限定软件点击过程。附带TTS声线样本是配置而非真人克隆，没有提供目标描述答案。

离线重建argv使用`{python}`、`{input}`、`{submission}`、`{output}`，必须从输入和提交的脚本/素材重建到output，不能仅复制已渲染主视频，不能重新调用收费TTS或联网。README列出依赖、版本、运行方法、实际增益。正式测试应隔离candidate目录并关闭模型网络；本地评分器执行重建本身不是操作系统沙箱。
