# 第12题 / Case31：四人会议字幕对轴·正式困难版

看完所附 Aegisub 教程，把 `input/source.mp4` 制作为准确、可读的英文多人字幕。文字已完整提供，不要求翻译。困难在于真实重叠、短附和、重复和自我修正、数值与否定，以及在镜头切换中保持声源身份。允许使用本地脚本和对齐模型。

## 输入

- `source.mp4`：AMI真实四人会议三个片段重排，259.48秒，704×576、25 fps。同步C/L/R机位每4秒切换，原声音速、音高不变；画面是听者时不可把声音归给听者。`original.wav` 为该输入视频实际解码声音。
- `transcript.txt`：完整逐词稿，文本组Uxxx的排列经过固定随机打乱，**编号和出现顺序均不代表时间或人物**。文本组是检索单位，不是必须采用的字幕分句。保留重复、口头词和未完成词；可改标点、大小写，但不得润色成与原声不同的句子。
- `speakers.json`及4组头像/声音：A/B/C/D是本题身份，不是原始语料库ID；以声音参考辨认人物。参考来自目标片段之外，可能含自然附和。
- `edit_boundaries.json`：公开拼接边界；不能让一个字幕事件跨越边界。段内时轴连续，段与段之间无语义连续性保证。
- `tutorial.mp4`和本地手册：依据官方文档制作的5分钟讲解，包含波形图，不是软件操作实录。

## 交付

交 `interview.ass`、`interview.srt`、实际烧录的 `preview.mp4`、`alignment.json`、`rebuild.json`、README和离线重建脚本。完整JSON格式见 `submission_schema.json`。

ASS的Name字段填A/B/C/D，画面上也显示身份标签。每人的事件独立对轴；同时发言在不同固定位置显示，不得重叠遮字。字幕必须放在底部32%区域（576高画面约y=392—575），顶部68%保留原画面以供完整性检测；建议四个固定角色槽、约20px字号并合理短分句，最多每人两行，必要时用完整底部宽度。SRT每行用 `A: ...` 等前缀，按所有事件边界分割成无重叠时间单元；仍持续显示的文本可跨相邻单元保持，不视为重复说话。ASS/SRT须在相同时间显示相同角色的相同词；技术切片不能改变实际可见寿命。允许拆分、合并同一角色相邻文本组。

真实重复与格式延续必须区分：同一角色再次说出与上一条完全相同的独立短句/回应时，ASS须保留两个独立事件，不能合成一次持续显示；SRT须在对应ASS边界显式开始新cue，即使文字完全相同。只有因其他角色进出而产生的持续文本技术切片才按同一次发言计算，评分器结合ASS重复事件边界核验。单个字幕内原本连续重复的词仍逐词保留。SRT cue数字编号可以不连续，但不得重复；alignment引用实际编号，不是文件内第几个cue。

常规字幕0.4—6秒；自然极短回应可短于0.4秒，但仍须可读。英文每行≤42字符，每位说话人最多2行，读速≤24字符/秒；同时发言最多4名角色，字号和分区应适配原尺寸。可在自然停顿适当延展显示，但需同时满足时间误差及镜头拼接约束。

`alignment.json.events` 为实际字幕事件映射：每项含 `utterance_ids`（涉及的U编号）、`speaker_id`、`start`、`end`、`ass_event_ids`、`srt_cue_ids`。ASS事件从1顺序编号，SRT使用文件cue编号，全部以字符串写入。一组稿件可对应多个事件；不得用映射JSON代替实际字幕。每个源文本组必须被映射覆盖。

视频原尺寸、帧率、时长及声音不变，字幕为唯一画面新增内容。48kHz音轨；不得删词、压低别人的声音、去掉重叠、补配音、改变音速或拼接。成片可由脚本生成，不考鼠标操作。

## 评分合同

100分，≥80且所有硬门槛通过才通过。自动项：时间30、角色15、重叠10、文本10、格式10、格式/映射一致性10、真实重建5；视听Judge评可读性10。精确配置见 `rules.json`。

硬门槛：两格式按角色token总体召回≥97%、精确≥99%，每角色召回≥95%；标注重叠词对保留≥90%，按官方重叠词对持续时间加权的同时显示召回≥85%（两cue仅碰一下不能通过）；时间质量≥0.75；格式合规比例≥95%；两格式时间语义等价≥98%；映射有效/覆盖≥98%。时间质量按真实字幕覆盖词的首尾边界：≤150ms满分，150—500ms线性降分，超过500ms零分；允许多种合理分句，不要求与私有标注唯一对应。原声归一化相关系数≥0.98，画面内容不得替换。

真实视听Judge必须核验：烧录字幕确实对应提交文件；否定和数值约束未反转；短回应、重复、自我修正未被删除；身份与提供声音参考一致；重叠时可以同时读到各人内容。Judge使用原片、实际成片/声音和私有标注，而不是只读提交JSON。两次独立评分，分歧第三次仲裁；模型仍无法确定或官方标注与声音有争议时进入pending，不将不确定性强判为失败。缺真实音视频API时总分为空，不用文本模型伪造视听分数。

`rebuild.json.argv` 使用 `{python}`、`{input}`、`{submission}`、`{output}`。评分器移走已有主视频后执行重建；脚本应从原输入与字幕生成到 `{output}`。不得只复制预先渲染的视频，不能运行时联网或付费调用。依赖和版本须写明，所有新文件和临时文件在D盘。

## 公开真值与考试边界

AMI官方有可下载的逐词、说话人、时码标注。因此本题不能宣称“互联网无答案”。本版本的新重排时轴、匿名身份和无序稿需要重新对应，但不能阻止有网络的模型检索原始标注再转换。若用于比较另一位Codex的能力，主办方应仅提供candidate导出包、隔离evaluator/authoring及原始语料目录，在预装工具后关闭网络；开放网络测试只能解释为工具/检索综合能力，不能宣称纯视听理解能力。

建议统一120分钟、8核CPU/32GB RAM、可选24GB GPU和30GB D盘空间；任何预算更改需事先告知。官方人工作词标注不是零误差逐音素认证；本包未生成正式正确字幕或参考成片，也未通过solver难度校准。来源和许可见 `CREDITS.md`，仅在本地构建，不冒称已获公开再分发全部附件的许可。
