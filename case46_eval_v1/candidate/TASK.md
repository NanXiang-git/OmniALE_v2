# 第14题 / Case46：消失的纸牌 · 中文口述影像探索试跑

为 input/source.mp4 制作中文口述影像，让能听见原声、但看不见画面的观众跟上重要的视觉信息。请实际生成可听看的成片，不要只写方案。本轮按公开SCORING.md暂行评分；不提供私有参考或旁白参考答案。

## 输入
- source.mp4：选定公开片段的剧情部分，148.064583秒，1280×720，24000/1001 fps，3550帧。已裁掉频道片尾；剩余画面及时间轴必须完整保留。
- original.wav：从本题主视频解码的48kHz立体声PCM原声。
- reference_zh.srt：辅助中文字幕草稿，详见 SUBTITLE_NOTES.md。不得把字幕边界当对白边界，也不得认为没有字幕就没有对白。
- glossary.json：译名与用语表，不包含视觉身份答案。
- tools/tts.py：本地TTS接口；player.html：可独立关闭旁白的播放器模板。

## 委托要求
1. 自行分析实际原声，找出对白间的空隙，再结合画面决定哪些信息值得讲。不给可用窗口。需要区分原声能表达的信息与必须靠旁白补充的信息。
2. 优先帮助观众跟上主体、关键动作、物件变化及因果。不要为了说全所有细节而塞满空隙；对白或明显音效已充分表达的信息可以不说。
3. 不要说错主体、虚构心理或提前透露尚未在画面中揭示的信息。不确定人物姓名可用清楚且一致的外观指代。
4. 旁白不得覆盖对白。中文措辞应短而自然，建议约3—4.5汉字/秒；必须实际合成并检查时长，不能只用字数估时。不得异常加速或截断词尾。
5. 不得暂停、变速、删镜头、补黑场或修改画面。字幕外挂，不得烧录旁白字幕或遮住原画面。保留全部原声；旁白出现时对原声做-6dB压低，可用50—100ms平滑起落防止爆音，结束后恢复。不得借压低原声来覆盖对白；注意关键音效保护。
6. 输出的base_track.wav为未加旁白、未局部压低的原声基轨；ducked_base_track.wav为按旁白安排压低的原声；ad_track.wav为全长旁白轨；mix.wav=ducked_base_track.wav+ad_track.wav。关闭旁白时播放base，开启时播放ducked_base+ad，画面与进度不变。四条轨从0开始、全长一致，48kHz立体声PCM。可统一降低整体增益以防削波，但须在README声明，保持旁白期间原声相对基轨低6dB。建议真峰值≤-1dBTP。

## 必交文件
- accessible.mp4：H.264/AAC，原画面与帧数不变，内置真实旁白混音。
- ad.vtt：中文旁白稿及实际安排时间；所有时间为主片相对时间。
- cues/：每条实际使用的配音WAV；不能静音占位，不可只交在线TTS链接。
- base_track.wav、ducked_base_track.wav、ad_track.wav、mix.wav。
- ad_plan.json：每条id/start/end/text/wav/visual_source_interval/knowledge_time，说明对应什么画面、信息最早何时可知；与VTT、配音实际时长一致。
- self_check.json：逐条报告实际配音长度、自己判断的对白重叠风险、是否重复原声、未完成或不确定之处。可附省略重要事件的理由。自查不等于正式评测。
- player_config.json、player.html：播放器可真实开关旁白。
- rebuild.json、rebuild.py（或其他离线脚本）、README.md：可用输入与提交的配音素材离线重建成片；不得仅复制成片、联网或重新调用TTS。
结构见 submission_schema.json。无需制作旧题的selection_audit.json，不要求达到固定事件数量。

## 执行条件
限时60分钟，含模型调用、分析、合成、渲染和自检；提前完成即冻结，到时终止全部子进程并保留当时文件。禁止子代理。输入只读；交付放/workspace/submission，临时文件放/workspace/scratch。
模型为gpt-6-luna，推理high，使用Codex harness。当前接口不支持原生音频输入；可用离线ASR、波形/频谱分析、视频抽帧及本地媒体工具，不可调用其他在线模型替代。工具的实际使用与局限须在README如实说明。
评分协议见SCORING.md；禁止寻找私有参考、历史答卷或评分器。
